## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - `01_eda.ipynb` – EDA (разведочный анализ).
  - `02_experiments.ipynb` – эксперименты и сравнение моделей по метрикам.
- `src/` – основной код проекта:
  - модули для работы с данными: `src/data/`;
  - выделение признаков: `src/features/` (лаг-фичи);
  - обучение/оценка/прогноз: `src/models/`;
  - запуск сервиса: `src/service/` (FastAPI).
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - `data/raw/oil_sales_synth.csv` (создаётся скриптом генерации).
- `configs/` – конфигурационные файлы:
  - `configs/.env.example` (пример env-переменных, без секретов).
- `tests/` – тесты (юнит-тесты, простые проверки) (опционально).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов:
  - `artifacts/model.pkl`, `artifacts/meta.json`, `artifacts/metrics.json` (создаются после обучения).
- `scripts/` – вспомогательные скрипты:
  - `scripts/generate_data.py` – генерация синтетического датасета;
  - `scripts/train_model.py` – обучение модели и сохранение артефактов.

Если структура проекта отличается от базовой, опишите это здесь.

## 4. Как запустить проект

Опишите, как именно воспроизвести основные сценарии использования проекта.

### 4.1. Запуск обучения модели

Процесс обучения состоит из двух шагов: генерация данных → обучение модели.

1) Сгенерировать синтетические данные:
```bash
cd project
python scripts/generate_data.py
```

После этого появится файл:
- `data/raw/oil_sales_synth.csv`

2) Обучить модель и сохранить артефакты:
```bash
cd project
python scripts/train_model.py
```

После обучения создаются:
- `artifacts/model.pkl` — обученная модель
- `artifacts/meta.json` — метаданные (версия, параметры)
- `artifacts/metrics.json` — метрики baseline’ов и финальной модели

### 4.2. Запуск сервиса (API/веб-интерфейс)

Сервис реализован на FastAPI и поднимается на порту `8000`.

Если используется Docker:

```bash
cd project
docker build -t oil-forecast:dev .
docker run --rm -p 8000:8000 --env-file configs/.env.example oil-forecast:dev
```

Опишите:

- на каком порту поднимается сервис:
  - `8000`
- какие эндпоинты есть (минимум – 1-2 ключевых):
  - `GET /health` — проверка статуса сервиса и загрузки модели
  - `POST /predict` — прогноз на горизонт до 30 дней
- как протестировать работоспособность (например, запрос через `curl` или браузер):
  - `GET /health`:
    ```bash
    curl http://localhost:8000/health
    ```
  - Swagger UI:
    - `http://localhost:8000/docs`

Пример запроса к `/predict` (сформировать запрос из последних 120 значений датасета):
```bash
cd project
python -c "import pandas as pd, json; df=pd.read_csv('data/raw/oil_sales_synth.csv'); h=df['sales'].tail(120).tolist(); print(json.dumps({'history': h, 'horizon': 30}))" > req.json

curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  --data @req.json
```
